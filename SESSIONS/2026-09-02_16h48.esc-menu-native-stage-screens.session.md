# ESC menu → the game's native stage / bonus selection screens

Date: 2026-09-02 16h48
Status: Planned (awaiting approval)

## Goal

Add buttons to craft's ESC menu (`src/craft/components/EscMenu.html`) that take the
player to the native stage-selection screens — both the ones the *pack* draws and the
one the *engine* draws, the latter being the only one that offers the BONUS list.

Asked in Spanish as "botones que lleven a las pantallas de selección de stage y bonus
nativas del juego"; when asked which of the two families was meant, the answer was
"las dos cosas".

## What exists, read from the packs and the engine

Dumped with `.tmp/scripts/dump-stagelist.py` (the pack's own `GameConfig.bin`), plus
`.tmp/scripts/dump-stagecode.py` / `scan-lselect.py` (new here) for the bytecode, so
none of this is a table typed from memory.

### The pack's own screens

| Screen | Category · scene | Sonic 1 | Sonic 2 |
| --- | --- | --- | --- |
| `LEVEL SELECT` (`LSelect/Act1`) | presentation (0) · 5 | yes | yes |
| `STAGE MENU` (`LSelect/Act2`/`Act3`) | regular (1) · last (19 / 21) | yes | yes |

- `LEVEL SELECT` is the classic list: zones, `SPECIAL STAGE`, `SOUND TEST`, and in
  Sonic 1 also SPINDASH / SPD CAP / ITEMS / MAX EMERALDS rows. Its entries are
  `AddMenuEntry` calls inside the `Menu Control` object, i.e. hard-coded in the pack.
- `STAGE MENU` is the mobile grid of zone icons. Both games' `Stage Menu` object ends
  in `stage.activeList = 1` — it can only ever load a *regular* stage.
- **There is no bonus-selection screen in either pack.** Sonic 1's bonus category is
  empty; Sonic 2's has 12 scenes (`EGG GAUNTLET ZONE`, `BOSS ATTACK 1-10`,
  `PROTO PALACE ZONE`) but nothing in the pack lists them: the only writes to
  `stage.activeList` in `LSelect` are `1` (Stage Menu) and the 2P VS results objects.

### The engine's own screens (Debug.cpp)

`initDevMenu()` → `DEVMENU_MAIN` → `DEVMENU_PLAYERSEL` → `DEVMENU_STAGELISTSEL`
(`PRESENTATION` / `REGULAR` / `SPECIAL` / **`BONUS`**) → `DEVMENU_STAGESEL` (the scenes
of the chosen list). This is the screen pair the request describes literally, and the
only native way to reach a bonus stage.

Facts that shape the design:

- Escape natively does `Engine.gameMode = ENGINE_INITDEVMENU`; `RetroGameLoop_Main`
  then runs `LoadGameConfig` + `initDevMenu()` + `ResetCurrentStageFolder()` on the
  engine thread. Nothing inside the dev menu re-checks `Engine.devMenu`, so the
  screens work with the SDK's `devMenu: false` default — only the Escape *shortcut* is
  gated, and craft swallows Escape anyway.
- `ProcessNativeObjects()` (which runs `processStageSelect()`) is skipped while
  `masterPaused`, so the overlay has to resume before the menu can be driven.
- `initDevMenu()` resets `playerListPos` to 0 — entering it from a Tails game would
  silently continue as Sonic unless the value is carried across.
- `setTextMenu(sm)` sets `stageMode` itself, so opening a specific screen is
  `setTextMenu(...)` plus, for the stage list, `gameMenu[0].selection2` (3/5/7/9 =
  presentation/regular/special/bonus) and `activeStageList`.
- `LoadConfigListText(&gameMenu[1], n)` takes a *file* list number: presentation 1,
  regular 2, special 3, bonus 4 — i.e. engine category {0,1,3,2} in that order, the
  same swap `dump-stagelist.py` documents.

## Plan

### Part A — the pack's screens (JS only)

1. `src/craft/services/game.service.js`: a `nativeScreens()` helper that reads
   `play.devMenu.getStageList()` and finds the pack's menu scenes **by name**
   (`LEVEL SELECT` in category 0, `STAGE MENU` in category 1 — names are matched
   trimmed, the pack pads them: `'STAGE MENU  '`). Returns only what the loaded pack
   actually declares, so a pack without one shows no button and nothing is hardcoded
   per game.
2. `src/craft/components/EscMenu.html`: a "Pantallas del juego" group with one button
   per found screen. Each closes the overlay (which resumes and returns focus to the
   canvas — the existing `closeMenu()`) and calls `play.devMenu.loadStage(cat, scene)`.

### Part B — the engine's dev menu (C++ bridge + wasm rebuild)

3. `scripts/build.sh`, WebDevMenu.cpp heredoc: add

   ```cpp
   void web_devmenu_open(int screen, int listIdx)
   ```

   `screen`: 0 main · 1 player select · 2 stage-list select · 3 stage select of
   `listIdx`. It records the request plus the current `playerListPos` and sets
   `Engine.gameMode = ENGINE_INITDEVMENU` — exactly what Escape does — so every
   graphics call still happens on the engine thread, not on the page's.
4. `scripts/build.sh`: patch `RetroGameLoop.cpp`'s `ENGINE_INITDEVMENU` branch to call
   `web_devmenu_apply_pending()` right after `initDevMenu()`, the same insertion trick
   the script already uses for `web_note_key_arrival()` in `RetroEngine.cpp`. That
   function restores `playerListPos` and applies the requested screen (`setTextMenu`,
   `selection2`, `activeStageList`, and for screen 3 the same `SetupTextMenu` +
   `LoadConfigListText` sequence `DEVMENU_STAGELISTSEL` runs on A).
5. `src/rsdkv4.sdk.ts`: `RsdkDevMenuBridge.open(screen?, category?)`, named
   (`'main' | 'player' | 'categories' | 'stages'`) rather than numbered, wired to
   `web_devmenu_open`. Add the export to `ENGINE_BRIDGES` so a stale cached
   `rsdkv4.wasm` is reported as such instead of failing silently.
6. `src/craft/components/EscMenu.html`: "Selección de stage (motor)" →
   `open('categories', 1)`, and "Bonus" → `open('stages', 2)`, the latter only when
   `getStageList()[2].stages.length > 0` (so it is absent in Sonic 1). Both resume the
   engine on the way out — the dev menu does not run while paused.
7. `make build-wasm` (Docker/emsdk) to rebuild `dist/rsdkv4/rsdkv4.{js,wasm}`, then
   `make build-craft` / the dev server to check it in the browser.

## Notes / risks

- Entering the engine's dev menu tears the running stage down (`ClearGraphicsData`,
  `ClearAnimationData`): the current run is lost, saves are not. The buttons should
  say so — the pack's own screens (part A) are the softer landing, the dev menu the
  "I know what I'm doing" one.
- `dist/` is gitignored and the wasm is built in CI, so between this change and a CI
  build every page with a cached wasm hits the SDK's cache-busting refetch path and,
  failing that, logs "rebuild it (`make build-wasm`)". That is the intended signal.
- The dev menu draws with `SystemText.gif` from the pack; both packs have it (it is
  what the native start menu already used before craft took that over).

## Verification

- `make typecheck` for the SDK change.
- `make build-wasm` completes and `dist/rsdkv4/rsdkv4.wasm` is newer.
- In the browser (dev server): launch Sonic 2, ESC → each of the four buttons reaches
  its screen; the BONUS list shows the 12 scenes and loading `EGG GAUNTLET ZONE`
  works; in Sonic 1 the bonus button is absent; the arrow keys drive the native
  screens afterwards (i.e. the ESC overlay gave the keyboard back).

## 2026-09-02 17h15 — Walkthrough (implemented, both parts)

Approved as "las dos cosas" (both families of screens). Built and verified in a real
browser; nothing was left for later.

### The pack's screens (JS only)

- `src/craft/services/game.service.js`: `PACK_SCREENS` (the menu scenes to look for)
  and `STAGE_LISTS` (the engine's category indices) next to the existing `STAGES`
  table, plus `gameService.nativeScreens()`. It reads `play.devMenu.getStageList()`
  and matches scene names **trimmed** (the pack pads them: `'STAGE MENU  '`), so the
  indices come from the loaded pack rather than a per-game table. With no engine up it
  answers everything-empty instead of throwing — the ESC menu is rendered then too.
- `src/craft/components/EscMenu.html`: the list is re-read on every open (`openMenu`),
  because the loaded pack can change between launches. `goToPackScreen()` closes the
  overlay *before* `loadStage()`: `loadStage` does not resume, so with the pause still
  held the scene would be requested and never drawn.

### The engine's dev menu (C++ + SDK + UI)

- `scripts/build.sh`, WebDevMenu.cpp heredoc: `web_devmenu_open(screen, listIdx)`
  records the request (plus the current `playerListPos`, which `initDevMenu()` would
  otherwise reset to Sonic) and sets `ENGINE_INITDEVMENU` — the same thing Escape does,
  so no graphics work happens on the page's thread. `web_devmenu_apply_pending()` then
  builds the screen on the engine thread, mirroring Debug.cpp's own transitions,
  including the two other numberings a stage list has (`selection2` on the menu, and
  the GameConfig list number `LoadConfigListText` wants, which swaps bonus and special).
- `scripts/build.sh`: a new python patch inserts `web_devmenu_apply_pending()` right
  after `initDevMenu()` in `RetroGameLoop.cpp`, the same insertion idiom the script
  already uses for `web_note_key_arrival()`.
- `src/rsdkv4.sdk.ts`: `RsdkDevMenuBridge.open(screen, category)` with named screens
  (`DEV_MENU_SCREENS` is the array whose index crosses to C++), `canOpen` so a host can
  hide the button on an older wasm, and `web_devmenu_open` added to `ENGINE_BRIDGES`.
- `EscMenu.html`: "Selección de stage" → `open('categories', 1)` and "Bonus" →
  `open('stages', 2)`, the latter only when the pack declares bonus scenes. Both are
  marked with an amber border and say "se pierde la partida en curso", because
  `initDevMenu()` clears graphics and animation data.

### Verification

- `make typecheck` clean; `make build-wasm` (Docker/emsdk) exit 0, and
  `web_devmenu_open` is in the rebuilt `dist/rsdkv4/rsdkv4.wasm`.
- `nativeScreens()` run against the **real** stage lists of both packs (dumped from
  `GameConfig.bin`, fed to the actual service module with its two imports stubbed):
  Sonic 1 → LEVEL SELECT cat 0/scene 5, STAGE MENU cat 1/scene 19, bonus 0; Sonic 2 →
  the same plus scene 21 and 12 bonus scenes; engine off → all empty.
- Headless Chrome over CDP (no new dependencies — Node 24's `fetch`/`WebSocket`),
  driving `dist/craft` behind the COOP/COEP preview server with a real `Data.rsdk`:
  all four buttons reach their screen. **The bonus screen the button opens is
  byte-identical (same SHA-256 of the screenshot) to the one reached by walking the
  native route** — ESC → Selección de stage → ↓ ↓ → Start. In Sonic 1 the bonus button
  is absent, as intended.
- Aside, unrelated to this change: reloading `/craft/` while an engine is running left
  the page wedged (a fresh browser was needed). Nothing here touches teardown-on-unload,
  but it is worth a look on its own.
