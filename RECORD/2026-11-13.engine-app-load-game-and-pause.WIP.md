## Goal
rsdkv4 ships its own `EngineApp` (engine-specs 0.4.0 contract) so any host — the launcher's
`/sonic1/`, `/sonic2/` — gets craft's save-slot screen and a pause menu, following engine-specs `UX.md`.

## Design
- **Where:** `src/app/app.js` + `src/app/app.css`, copied to `dist/rsdkv4/app/` with the art it needs
  (`assets/stages-sonic1|2/*.png`, `assets/player-*.svg` from craft). Plain JS + DOM: the only import
  is `../engine-specs.js` (already shipped next to the SDK) and `../rsdkv4.sdk.js`. No jq79, no bundler.
  Part of `make build-sdk` (target `build-app`), so the release tarball and npm package carry it;
  `package.json` exports `./app`.
- **`mount(target, host)`:** boots `Rsdkv4SDK` into a stage with `startMenu: 'host'`,
  `host.assets` / `host.storage`; while it boots the screen shows the game's art and "Arrancando…".
- **Load-game screen (craft):** NO SAVE card + four slots. A slot with data: zone portrait, zone tag,
  character, zone name, the seven emeralds, lives and score, *Continuar*. An empty slot: character
  picker (only the pack's `players()`), *Jugar*. Zone table and emerald count moved from craft's
  `game.service.js` into the app (craft keeps its own copy for now). Pack from `play.game.type()`.
  Slots refresh on the SDK's `saves` event.
- **Controls (UX.md):** ←/→ (LB/RB too) move between cards; ↑/↓ on an empty slot changes character;
  A/Enter plays; Y/V on a filled slot asks to delete it; B/Esc at this top level asks before leaving
  (`host.exit()`). Mouse/touch work the same (hover focuses, click activates).
- **In game:** input suspended; Select+Start or Escape → pause: *Continuar*, *Cambiar de partida*
  (back to the slot screen; `game.start()` works mid-game), the pack's own screens (*Level select*,
  *Stage menu*, when the pack declares them), *Volver al lanzador*. B / Start closes.
  Engine paused with owner `app` while a menu is open.
- **Unmount:** input listener off, engine destroyed, DOM removed.
- **Launcher:** `engines.json` rsdkv4 gets `"app": "app/app.js"`.

## Out of scope
Options screen (engine GAME OPTIONS rows), craft migrating onto the app, the BlastEm app.

## Extension · 2026-11-13 — Walkthrough (implemented)

- `src/app/app.js` — `mount(target, host)` → `{ unmount() }`. Boots the SDK (`startMenu: 'host'`)
  under a boot screen (game art + status), then the load-game screen. Screens: `boot`, `slots`,
  `game`, `pause`, `confirm` (layered on the screen it was asked from), `error`. Zone table,
  `describeSlot()` and `emeraldCount()` exported (same data as craft). Pause items: Continuar,
  Cambiar de partida (slot screen, Back returns to the pause menu), the pack's Level select /
  Stage menu when declared, Volver al lanzador (asks first). Delete a slot with Y/V (asks first).
- Imports only `../rsdkv4.sdk.js`; styles read engine-specs `--wg-*` tokens with the same values
  as fallbacks, so it works with engine-specs 0.3.2 (no 0.4.0 runtime needed).
- Bug found and fixed: re-rendering replaced the cards under a resting cursor and the browser's
  fresh `pointerover` stole the pad's focus on every key — hover now follows real `pointermove`s.
  On narrow screens the card row scrolls sideways and keeps the focused card centred (by hand, no
  `scrollIntoView`, which would scroll the host page).
- `src/app/app.css`; Makefile `build-app` (part of `build-sdk`) → `dist/rsdkv4/app/` with craft's
  stage portraits and character art; `package.json` exports `./app`, ships `src/app/`.
- Verified in Chromium through play.germade `/sonic1/` with a seeded `SData.bin` (Green Hill 2 as
  Tails; a special stage): cards, character picker, delete confirm, exit confirm, continue →
  game, Escape → pause, change save → slots → Back → pause, exit → home `?focus=sonic1`; mobile.
  Not verified: a real Data.rsdk (none here) — characters list and pack screens come from it.
