# Keyboard: A/S/D + Z/X/C + arrows, as the other Sonics

_2026-11-14_

## Context

Owner decision for the three Sonics (rsdkv5 already done in its PR #3): "ABC -> ASD, XYZ -> ZXC",
and for rsdkv4 "igual que el resto: ASD+ZXC+flechas". Today rsdkv4 uses the decompilation's
defaults (Z/X/C = A/B/C, A/S/D = X/Y/Z, Q/E = L/R) and this build's patched `ProcessInput()` adds
W/A/S/D as a second set of directions, taking A/S/D away from X/Y/Z. With the new map A/S/D are
face buttons, so the WASD alias has to go.

## Plan

1. `scripts/build.sh` (the `ProcessInput()` patch): drop `isWasdAlias()` and the W/A/S/D cases in
   `isKeyHeld()`; a key is held when its own `keyMappings` scancode is (still bounds-checked).
   Rebuild the wasm.
2. `src/rsdkv4.sdk.ts` `buildSettingsIni()`: write `[Keyboard 1]` with SDL scancodes — Up 82,
   Down 81, Left 80, Right 79, A 4 (A), B 22 (S), C 7 (D), X 29 (Z), Y 27 (X), Z 6 (C), L 20 (Q),
   R 8 (E), Start 40 (Enter), Select 43 (Tab). Exported as `RSDKV4_KEYBOARD_1`. A host's own
   `assets.settings` still wins. `ENGINE_KEYS`: the WASD entries go, the bound letters stay.
3. `src/rsdkv4.options.ts` `RSDKV4_INPUT.keyboard`: the same map in `KeyboardEvent.code`; comment
   about WASD removed.
4. Craft demo: `input-probe.service.js` CODES (no WASD; a/b/c = A/S/D, x/y/z = Z/X/C) and the
   key hints in `GameLauncher.html`. `input-doctor` (the ghosting probe) gets the same keys.
5. Release: goes with the open dialog fix (PR #5) as one release — **minor**, since the default
   keys change.

**Verify:** `make test`; rebuilt wasm with the real Sonic 1 data in Chromium: A jumps / confirms,
Z does not, W does not move.
